后续 CI 复查：[导出批次的一次远端浏览器运行](https://github.com/luojierochester/Information-DIet-Manager/actions/runs/37053978602)在快照时间断言处失败。原因是测试在抽屉重新请求第一页时，仅凭旧的 50 行仍在页面上就判断加载完成，提前记录了上一份快照时间；后续点击分页又自动等待了新请求完成，导致比较跨越两份快照。这属于验收脚本的等待竞态，不能把该次运行记为通过，也不应通过删除时间一致性断言掩盖。修复使用真实第一页响应与受控延迟验证加载边界，产品界面与数据逻辑保持不变；最终结果以修复提交的 CI 为准。

修复后的前端真实浏览器生命周期验收在本机完整通过 26 个场景，保留快照时间一致性、全部 URL 和无重复分页断言，并验证重新加载期间旧记录可见但分页禁用。测试请求经过真实后端，未修改产品前端代码；本地通过不替代对应提交的远端 CI。

最初 Python 审计只列出 28 包，漏了 packaging；后续已经复现、更正并加入防漏门禁。不要再引用旧 28 包结果作为完整覆盖。各批次测试数量反映当时范围，不能相加当作最终独立测试数。[GitHub Quality 结果](https://github.com/luojierochester/Information-DIet-Manager/actions/workflows/quality.yml)需对应具体提交查看。

整数边界批次本地最终后端回归 **302 项通过**，包含新增 25 项真实 HTTP / 临时数据库测试；1 条既有 Starlette/httpx 弃用警告仍在。实际达到 SQLite 最大正整数的已存在任务仍返回 200，未完成任务仍返回 409；超界或不存在的任务统一返回 404。旧分页实测已有保护，因此没有为了增加改动而重写。

额度恢复后继续完成轮询和导出批次，本地完整 Python 检查 **386 项通过**（后端 360 项、工程脚本 26 项，另报告 26 个 unittest subtest，不重复相加）；前端单元 35 项、扩展单元 38 项、前端真实浏览器 29 场景、扩展真实浏览器 10 场景通过，生产构建通过。新增加的 58 项导出回归包含 31 项预算/合同测试和 27 项真实 ASGI 交付测试，覆盖慢消费者、生成阶段重复取消、两种 ASGI 断连方式和临时文件实际删除。独立审查期间发现并修复了准备期取消提前释放容量以及关闭错误覆盖原响应两项问题。模板/样式与该批修改前逐字一致；模型图表验收仍有合成输出，不代表真实模型效果。

## 已有工程基础

- 最小应用与模型环境分开；个人数据库默认位于每用户目录，能力密钥分管理员和采集器，接口限制本机访问。
- 页面备份、恢复和删除有事务及失败回归；分析失效不再伪装为可信图表，保存页数与有效测量数量明确区分。
- 有真实 API、临时 SQLite、独立浏览器集成和 Windows CI；维护批次接受独立复核并留下可追踪提交。
- 视觉和功能边界明确，质量工作没有变成重新设计产品；数据修复保留原界面结构。
